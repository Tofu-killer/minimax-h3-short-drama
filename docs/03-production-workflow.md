# 03 · 用 MiniMax H3 制作高清短剧：端到端工作流

> 这是本项目的核心文档。它把官方文档、三个开源短剧生成项目（Hailuo‑AI‑Short‑Drama‑Studio、火宝短剧 huobao‑drama、MiniMax‑H3‑Codex‑Drama）、MiniMax 官方 skills、B 站/公众号教程与多篇提示词指南中的做法**合并成一条可执行的流水线**。每一步都标注「谁在这么做」，方便追溯。

## 0. 一张图看懂

```
 剧本/小说 ──► ① 改写为分集剧本 ──► ② 资产提取(角色/场景/道具) ──► ③ 资产定妆图(多角度)
                                                                         │
      ┌──────────────────────────────────────────────────────────────────┘
      ▼
 ④ 分镜拆解(8–15s 一段，内含 2–4 子镜头) ──► ⑤ 分镜首帧图(可选) ──► ⑥ H3 提示词(官方三段式)
      │                                                                       │
      │              ┌────────────────────────────────────────────────────────┘
      │              ▼
      │   ⑦ 批量生成: 768P 草稿 ×N 候选 ──► 人工/自动选片 ──► 2K 重生成(或直接 2K)
      │              │
      ▼              ▼
 ⑧ QC(身份/服装/口型/音频/字幕安全区) ──► ⑨ FFmpeg 拼接 + 字幕 + 配乐 ──► ⑩ 成片 1080×1920 / 2K 交付
```

每一段 H3 生成 = 一个「分镜段落」(segment) = 一次 API 调用，产出 4–15 秒、自带对白与音效的多镜头片段；一集 60–120 秒的竖屏短剧由 6–12 段拼接而成。

## 1. 为什么短剧流水线围绕「段落」而不是「镜头」

传统 AI 短剧（Hailuo 2.3 / Seedance 1.x 时代）一个镜头一次生成，然后外挂 TTS + 口型驱动。H3 改变了单位：

| 维度 | 旧流程（单镜头 + 外挂配音） | H3 流程（段落 + 原生音画） |
|------|----------------------------|---------------------------|
| 生成粒度 | 3–6 秒单镜头 | 4–15 秒，内部可含 2–4 个镜头切换（`[Shot 2] At 00:04.500, the camera cuts to…`） |
| 对白 | TTS 后期贴 + 对口型工具 | 提示词内 `<d>[Chinese] 台词</d>`，模型直出人声 + 口型 + 环境音 |
| 正反打 | 两次生成，人物易漂移 | 一次生成内完成，同一上下文保证两人脸型/服装一致 |
| 一致性 | 单图 S2V 主体参考 | 最多 9 图 + 3 视频 + 3 音频全能参考，角色/场景/音色分别锁定 |
| 成本 | 单价高 + 配音/口型额外付费 | 2K $0.13/s，音频免费 |

火宝短剧 `storyboard-breaker` skill 的定义最简明：**"一个分镜 = 一个分镜段落（segment）= 一个视频生成任务"**，段落 8–15 秒、含 2–4 个子镜头、子镜头 2–6 秒、可切角度但不可跨场景（`scene_id` 是段落级绑定）。

## 2. 阶段详解

### ① 剧本 → 分集剧本

- **输入**：小说原文 / 一句话创意 / 已有剧本。
- **做法**：LLM 「编剧 Agent」改写。Hailuo‑AI‑Short‑Drama‑Studio 的大纲 system prompt 定了短剧黄金准则：
  - 前 3 秒生死线：开头必须有强动作或悬念直接切入；
  - 高密冲突：每集至少 2 个小反转或 1 个重大冲突升级；
  - 强钩子结尾：每集结尾留下诱导点击下一集的悬念。
- **节拍模板**（hailuoai.video 官方短剧工具页）：Hook 0–3s「从事件中间开始」→ Setup 3–8s「一句话交代」→ Turn 8–14s「反转」→ Cliffhanger「停在未解决的画面上，用尾帧锁住」。
- **台词长度**：aiworkflows 建议每句对白 < 12 个英文词；火宝的硬规则是 **段落时长 ≥ 台词与旁白总字数 ÷ 4.5 字/秒 + 2 秒表演余量**，放不下的台词挪到下一段。
- **输出**：JSON 结构（title / genre / synopsis / characters[] / episodes[]），模板见 `templates/director-system-prompt.md`。

### ② 资产提取

- LLM 「提取 Agent」从剧本里抽出 **角色 / 场景 / 道具** 三类资产并去重（火宝 `extractor`）。
- 每个角色产出一张「角色卡」：姓名、定位、性别、体型、性格、外貌描述、**固定识别短语**（后面每个镜头提示词都原样复用这句，不要换说法）。
- 每个场景产出「场景卡」：地点、时间、光线、关键陈设；**场景图里不出现人物**（MiniMax 官方 3d‑animation skill 的规定："scene cards must show environments only"）。

### ③ 资产定妆图（视觉事实源）

这一步决定整部剧的一致性上限，所有来源都把它列为最关键步骤。

- **工具**：任意强图像模型。国内教程用海螺 AI 内置的 🍌Pro（Nano Banana Pro，4K、一次 4 张）；Codex‑Drama 用 GPT‑Image；aiworkflows 推荐 Midjourney `--cref` + 固定 `--seed` 或即梦。
- **每个角色至少 3 张**：正面中性表情头像、3/4 侧面、全身服装图；同一光线、同一服装。CSDN 工程实践文章进一步建议**多角度 + 环境光尽量接近最终镜头**。
- **道具**：白底单品图，作为视频参考（火宝）。
- **风格锁**：项目级统一一句视觉风格（写实 / 3D / 国漫），注入所有图像提示词（火宝「项目风格」+ Codex‑Drama "Global Visual Style Lock"）。
- **命名**：`char_<id>_front.png` 等，后续按 `<Picture N>` 顺序引用。

### ④ 分镜拆解（Storyboard Breaker）

LLM 「分镜 Agent」把每集剧本切成段落。合并火宝与 Short‑Drama‑Studio 的规则：

```
总时长 ≈ 剧本字数 ÷ 500 字/分钟
段落数 ≈ 总时长 ÷ 12 秒，允许 ±20%
过渡段 8–10 s；叙事段 10–15 s；爆点段 12–15 s
每段 2–4 个子镜头，每个子镜头 2–6 s
禁止连续两段都是静态对话；每 3 段必须有一次中/全景大调度或动作急转
```

每段字段（见 `pipeline/examples/episode01.json`）：

| 字段 | 说明 |
|------|------|
| `segment_id`, `duration` | 4–15 整数秒 |
| `scene_id`, `character_ids`, `prop_ids` | 绑定资产，不得发明不存在的 ID |
| `shots[]` | 每个子镜头：`start`（第一镜不写时间码）、景别、角度、运镜、动作、`dialogue[]`（speaker / language / text / delivery） |
| `soundscape`, `music` | 环境音与配乐，不写空泛情绪词 |
| `first_frame_prompt` | 可选，对应第一个子镜头的静帧，用于 I2VA |
| `continuity` | 从上一段继承的服装/道具/光线/方向 |

Short‑Drama‑Studio 还要求每段写出 **first_frame / last_frame 状态**和精确到 0.1 s 的 **action_beats**（`[0.0s - 1.8s]: 男子推门而入; …`），H3 的时间码写法正好能承接。

### ⑤ 分镜首帧图（可选但推荐用于关键镜头）

- 用角色定妆图作参考，生成该段落第一个子镜头的静帧（9:16）。
- 适用：主角大特写、必须精确构图的钩子镜头、跨段落衔接镜头。
- 不适用：以动作/运镜为主的过渡段，直接 Ref2VA 更省。
- **衔接技巧**（国内「漫剧」教程）：取上一段**尾帧**和下一段**首帧**，用 FL2VA 生成 2–4 秒转场段；或者直接把上一段尾帧作为下一段的 `first_frame`。

### ⑥ 写 H3 提示词

详见 `docs/04-prompt-engineering.md`。要点：

1. 用官方三段式：`integrated_multimodal_description` / `overall_soundscape` / `non_diegetic_music`。
2. 子镜头用 `[Shot 1]`、`[Shot 2] At 00:04.500, the camera cuts to …`，第一镜不写时间码。
3. 台词：`角色 (S1) says: <d>[Chinese] 你到底瞒了我多久？</d>`，一镜一人说话，口型才稳。
4. 一镜一个主运镜，使用官方运镜词表（Push In / Pull Out / Pan / Truck / Tilt / Arc / Tracking / Static / POV …）。
5. 参考模式下为每个参考文件分配**唯一职责**：`<Picture 1>` 锁脸、`<Picture 2>` 锁服装、`<Picture 3>` 只给环境、`<Audio 1>` 只给音色。
6. **先过一遍 H3‑Context‑IR**（$0.01–0.03/条），把中文分镜改写成结构化英文描述，再把中文台词保留在 `<d>` 里。

### ⑦ 批量生成与选片

- **并发**：每段一个任务，`asyncio` 并发提交（Short‑Drama‑Studio 宣称 30 段/集并行，但其代码实际是顺序 await；本项目参考实现用 `asyncio.Semaphore` 真正并发），`callback_url` 或 10 秒轮询。
- **两档策略**：
  - 草稿：`768P` × 2 候选 / 段（$0.08/s）；
  - 成片：中选候选走 `video_regeneration` 到 2K（$0.05/s），或关键镜头直接 `2K`（$0.13/s）。
- **多候选**：ugcmaker 与所有教程一致建议每段 2–5 次生成再挑。Codex‑Drama 的默认是普通镜头 1 个有效 take，关键镜头最多 2 个。
- **幂等**：以 `segment_id + prompt hash` 做键，已成功的段不重跑（Short‑Drama‑Studio 的 `shot_ids=None` 跳过已有任务）。
- **内容审核失败（1026）**：火宝的处理是提示用户换模型重试；更稳的是让 LLM 自动把触发词（真人名、血腥、亲密）改写为间接描述后重提一次。

### ⑧ QC（质检）

Codex‑Drama 把 QC 拆成两层，值得照搬：

- **技术 QC（脚本自动）**：ffprobe 校验分辨率 / 时长 / 帧率 / 音轨存在、峰值电平不削波；时长与请求一致。
- **视觉 QC（人工看联络表）**：身份（脸）/ 服装 / 道具几何 / 环境 / 连续性（方向、光线）/ 字幕安全区 / 叙事是否符合分镜。规则：**技术通过但视觉未审 ≠ 整体通过**；硬门禁不过只允许重试一次。
- **音频 QC**：抽样听对白是否与 `<d>` 内文本一致、语言是否正确；多说话人时检查是否「错人开口」。

### ⑨ 剪辑合成

- **FFmpeg concat**（火宝、Codex‑Drama 均以 FFmpeg 为 v1 后端）：先把所有段统一转码为同一编码参数，再 `concat demuxer` 拼接，避免重编码导致的音画不同步。
- **字幕**：H3 原生音频有台词，但模型**不会**可靠地渲染精确文字，字幕一律后期烧录（Codex‑Drama："add labels deterministically afterward"）。字幕来源就是分镜 JSON 里的 `dialogue[]`，带时间码。
- **配乐**：若段落内 `non_diegetic_music` 写了 `N/A`，统一在剪辑阶段铺全集配乐，避免各段配乐风格打架；硬切点对齐节拍（官方 music‑video skill：切点落在 1/4 或 1/8 拍）。
- **开头 3 秒**：剪到最紧；片尾加「下一集」卡片（aiworkflows）。
- 也可以导入剪映 / CapCut / PR 手工精剪，国内教程多走这条路。

### ⑩ 交付

- 竖屏 `1080×1920`（2K 直出为短边 1440，可下采样）；`30fps` 或保留 24fps；AAC 立体声。
- 产物目录建议（Codex‑Drama）：`planning/ profile/ prompts/ images/ clips/ audio/ subtitles/ edit/ qc/ final/ logs/` + `project.yaml`，保证**可复现**：任何一段都能从 prompt + 参考文件重新生成。

## 3. 三条典型路线对比

| 路线 | 适合谁 | 工具链 | 一致性手段 | 单集成本（60 s 竖屏） |
|------|--------|--------|-----------|------------------------|
| **A. 纯 API 全自动** | 要做上百集的工业化团队 | LLM 编剧/分镜 Agent + H3 API + FFmpeg（本项目 `pipeline/`、火宝、Short‑Drama‑Studio） | Ref2VA 多图参考 + 固定识别短语 | 768P 草稿 ×2 + 2K 重生成 ≈ $13 |
| **B. 海螺 AI 应用手工** | 个人创作者、漫剧 | 海螺 AI 生图(🍌Pro) → 海螺 Video(首尾帧/参考) → 剪映 | 定妆图作参考 + 相同人物描述 + 负向约束 | 会员积分 |
| **C. 本地 ComfyUI** | 有多卡 GPU、要规避按秒计费 | 开源 H3 Base FL2VA/Ref2VA + Turbo LoRA + ComfyUI（Codex‑Drama、RunningHub 工作流「多参分镜硬控流」） | 同 A，另有 Qwen Image Edit 一致性工作流 | 电费；但只有 768P，没有 IR 和 2K |

## 4. 时间预算（aiworkflows 实测）

首集 3–6 小时（剧本 45 min、定妆与分镜图 60 min、视频 120 min、配音 40 min、剪辑 60 min）；**系列圣经与角色参考锁定后降到约 2 小时/集**。用 H3 原生音频可以去掉配音环节。

## 5. 常见失败与对策

| 现象 | 原因 | 对策 |
|------|------|------|
| 角色换脸 / 换衣 | 文字描述漂移、参考图没分配职责 | 每段复用同一组 `<Picture N>` + 同一句识别短语；`Image 2 controls outfit only` |
| 台词被错的人说 / 变成含糊音 | 没写说话人或语言 | `(S1) says: <d>[Chinese] …</d>`；一镜一人 |
| 旁白时人物张嘴 | 未声明画外音 | `says in an off-screen voiceover … while his lips remain completely closed` |
| 画面像幻灯片 | 没有触发→变化→结果的动作链 | 写 action_beats；每镜一个可观察事件 |
| 运镜乱飘 | 叠加多个运镜 | 一镜一主运镜 + 幅度/速度词 |
| 文字招牌拼错 | 模型不擅长精确排版 | 后期叠字 |
| 1026 内容审核 | 真人名、血腥、亲密描述 | LLM 自动改写后重试一次 |
| 16:9 裁 9:16 糊 | 后期裁切损失像素 | 一开始就 `ratio: 9:16` 或 9:16 首帧图 |
| 续写段落背景变化 | 视频延展空间连续性不完美（MindStudio 实测） | 用上一段尾帧做 `first_frame`，而不是把整段视频当参考延展 |
