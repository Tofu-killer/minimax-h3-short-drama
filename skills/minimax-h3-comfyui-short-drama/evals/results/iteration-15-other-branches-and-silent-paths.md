# 迭代 15：换一条路线的第六次独立测试——「悄悄走错」的几条路（2026-11-23）

第六次测试和第五次用的是同一台测试机（真实的 ComfyUI 0.37.2 + 微型随机权重 H3），换了剧情结构，专门走前几次没走过的分支：第一段开场两张正脸（按文档该用 `i2va`），第二段过肩开场、第二镜要按设计的构图出（`ref2va` + 首帧 + 关键帧），一个角色有录音、另一个没有，项目要营利。另外指定了六件事中途去做：首帧出完之后改主意重做、把不是采纳的片段和精修的副本分别放进剪辑、改了分镜之后仍然采纳旧草稿再精修、用和草稿不同的画布从保留的 latent 精修、手改一句字幕时间再混音、提交途中打断再重跑。H3 任务用了 8 个（上限 10），160 次工具调用，155 份日志。

和上一轮一样，权重是随机的，画面是噪声：验证的是流程和工具，不是画质。

## 结论

| 问 | 答 |
|----|----|
| 只凭 skill 能不能做出第一批草稿 | **能**。从自检到两批草稿，每条文档里的命令都照写的跑通了；这台机器上证明不了的：真实出图、Sage、显存 |
| 能不能做到成片 | **部分能**。链路走得完，也如实报告；但有四条路能把错的图或错的片段悄悄放进成片 |

它确认不用猜就能做的：自检、连通与冒烟测试、校验器、全部 12 条出图命令（预检通过）、提示词生成与检查、草稿的提交 / 中断续取 / 相同任务跳过、`observe_take.py`（`--small-ok`、`--stale-ok`、`CHECK THE CUT`）、两个系列各自从保留的 latent 精修、字幕时间的手工锁定、OTIO 和剪映导出。上一轮新加的东西它都验到了：剪辑单认出不是采纳的片段、认得出精修的副本；`--stale-ok` 采纳的片段照提示用自己留的 `media.json` 精修成功；预览尺寸的片段被拒收并给出 `--small-ok`；校验器在图还没做时列清单而不是报错。

## 四条「悄悄走错」的路，和处理

| 它发现的 | 后果 | 处理 |
|----------|------|------|
| 两步出的首帧（先人物和场景、再放道具）：第一步重做之后，第二步——视频真正用的那张——仍然显示「已有」，没有命令也没有提醒 | 这一段的每条草稿都从旧首帧开始 | `plan_stills.py` 记下每张图是从哪几张输入图做出来的（按内容）。输入图换了，它就标 `MAKE AGAIN` 并写明原因；face.png、场景裁切重做之后，用到它们的首帧同样会被标出来 |
| `--from-latent` 精修时画布和草稿不一样：只有一句警告，`--confirm` 照样提交、照样跑完，出来的片段和正确做法的不一致，剪辑单还把它当作正常的精修 | 最长的一类任务白跑，交付错的片段 | 画布和帧数不再要人给：脚本从那条草稿的 `run.json` 里读出来直接设到 H3 节点上，文档里那条不带尺寸的命令现在自己就是对的（生成的任务和手工给对尺寸的逐字节相同）。只有自己 `--set` 了不一样的值才警告；警告在确认行之前再醒目地重复一次，带着警告提交的片段把警告写进 `run.json`，`make_edl.py` 放它进剪辑单时再提醒 |
| 精修好的片段放进 `selects/` 之后重跑 `make_edl.py`：悄悄沿用草稿；同一段两个文件时按字母序取第一个（草稿），`--overwrite` 还会丢掉手工锁定的字幕时间和配乐设置 | 精修白做，成片里是草稿 | 一段两个片段不猜：`AMBIGUOUS`、退出码 2，原来的条目先留着；后放进来的片段会被点名并给出换过去的 `--pick`；`--overwrite` 只重建各段条目，剪辑单自己的设置保留；片段内容和入点没变时，手工锁定的台词时间跟着留下 |
| `--back` 排了背面视图，但过肩首帧的命令里那个人接的仍是正脸图，背面图一做出来提醒还消失了 | 候选白出，脸被画到后脑勺上 | 镜头写着 `over the shoulder of {id}` 时，这个人的图像输入接背面视图；背面图在盘上之后不用每次再带参数。提醒只在首帧确实给了这个人正面图时才出现 |

## 其余缺口

| 缺口 | 处理 |
|------|------|
| 只改了第二镜的动作，`build_prompts.py` 却提示「首帧是按之前的开场做的，重做它」 | 只在开场状态真的变了的时候才提示 |
| 文档说「同提示词换个 seed 再出一张，用清单里那条命令」，可图在盘上之后清单里就没有命令了 | 已在盘上的图下面保留它的命令 |
| 文档说挂音色样本会改变样本出处那一段的提示词；那一段是 `i2va` 时并不会 | 文档和提示改成「`ref2va` 段」；`i2va` / `fl2va` / `t2va` 段接不了音色参考 |
| 两处说二采「没有跑过」，另一处说执行过；首次开工清单说「没采样过」 | 统一成实际情况：用微型模型执行到了出片，真实权重没有跑过 |
| 一处说 51 行 `ERROR lora` 可以忽略，另两处说该换 LoRA | 统一：任务不会中断、那 51 个模块被跳过；「贡献很小」是未经验证的社区说法，默认仍换 v1.0 |
| 营利项目「可以不下 Qwen-Image 2.1」，但下载脚本没法只跳过它（17 GB） | 模型分组拆成 `t2i`（Qwen-Image 2.1）和 `edit`（Edit-2511），`stills` 仍是两者之和；营利项目用 `--sets ref2va edit zimage refine` |
| 文档引用了安装包里没有的 `evals/results/…` | 写明记录在 GitHub 仓库里，安装包不带 |
| `i2va` 段配了 Ref2VA 的工作流，只说「导出一个建在那个节点上的工作流」 | 直接说该用附带的 `h3_fl2va*.api.json` |
| 按文档做「关 Turbo 的 20 步重拍」，预览警告「这次不会复现那条草稿」 | 只有精修才是要复现草稿的；草稿工作流换设置重跑，改成普通说明：这是另一条片段，要重新选、重新观测 |
| 场景母版的提示词里写着 `with nobody in it`，而文档说 CFG 1 的模型里不要写被排除的名词 | 改成不带那个名词的写法（`unoccupied`） |
| 出图清单说场景裁切「每张首帧一个」，实际是每段一个 | 改了说法 |

## 这一轮自己加的

- **`check_setup.py`**：只读地问正在运行的 ComfyUI——版本、PyTorch 是不是 CUDA 13 的构建、启动参数、显存和内存、附带的 18 个工作流各自缺哪个节点包、哪个模型文件（放深了一层也认得出）。第 0 步里要手工抄的东西大半由它代劳。对着测试机上两台真实的 0.37.2 试过。
- **同名替换片段**：把新片段用同一个文件名覆盖进 `selects/`，文件名和帧号都没变，原来的检查看不出来。现在剪辑单的每个条目记着片段内容的指纹，字幕对时和混音报告也记着；`make_edl.py`、`mix_episode.py`（含 `--dry-run`）和两个导出脚本都会指出「这是按旧片段量的」。
- **官方生态索引收尾**：之前没提过的 110 个仓库逐个看了 README 并分类（`docs/13-github-survey/14-index-triage-2026-11-23.md`）：21 个和本地 ComfyUI 上的 H3 视频有关，没有一个需要改动默认做法。带回一条核实过的事实：NVFP4 的文本编码器在 4090 上是「模拟」运行（原生运算要 50 系），日志里 `emulated ops: nvfp4, mxfp8` 属正常，文件照用。
- 上游核对：Turbo LoRA 仓库 11 月 16 日之后没有新文件，ComfyUI 最新仍是 v0.46.2。

## 没有做的

- 真权重下的一切（画面、口型、耗时、显存）、Sage 的两个节点、DynamicVRAM 加载路径、Windows。
- Z-Image-Turbo 和 Qwen 的出图工作流仍然只通过了服务器校验。
- 测试没有用到的：`--seed` 重跑一采的精修、分块精修、`--anchor` 的实际执行（任务数上限）——这几样上一轮和更早用微型模型执行过。
- 「画布不一致的精修和正确做法差 PSNR 35.9 dB」是测试在随机权重上量的，只说明两者不是同一条片段；真模型下差多少没有量过。
