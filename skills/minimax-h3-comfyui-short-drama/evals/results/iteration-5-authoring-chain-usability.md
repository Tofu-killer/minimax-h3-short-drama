# 迭代 5：创作链路的独立可用性测试 + 对照官方原文的复核（2026-11-21）

分两步：先请一个没有任何上下文的 agent 走一遍创作链路，把它报的问题修掉；再把修完之后脚本出的提示词逐条对着 MiniMax 官方指南原文（`ref-en.txt` / `base-en.txt`）和 ComfyUI 源码核一遍。

## 第一步：独立可用性测试

**做法**：agent 只读 `SKILL.md` 与它指到的 reference，拿一段两人、两个场景、一件道具的短剧剧本，完成「资产表 → 分镜 JSON → 校验 → 分镜表 → 节奏审计 → 提示词 → 机检 → ComfyUI 批次预览与选片卡 → 采纳一条片段后把实拍末态接给下一段」。没有 GPU；ComfyUI 用一个只模拟 HTTP 接口的本地服务代替；「片段」用现成素材顶替。它被要求只用 skill 的脚本，并如实报告每一处卡住、猜测或看起来不对的输出。

**结果**：链路走通，交付了分镜、三段提示词、批次预览和选片卡。它报回的问题里，属于脚本或文档**错误**的有这些（逐条计数没有留存，下面按性质归并）：

| 发现 | 性质 | 修复 |
|------|------|------|
| `camera` 字段里的 `{资产id}` 没被替换，原样进了提示词 | 缺陷 | 所有进提示词的字段统一替换；`validate_episode.py` 检查每个占位符都绑在该段上；`lint_prompt.py` 对残留的 `{…}` 报 ERROR 并指出位置 |
| 字段原样拼进去之后不成句（`delivery` 写成形容词、`continuity` 写成指令、`performance` 带 `trigger:` 标签） | 缺陷 + 文档 | `02-storyboard.md` 给每个字段规定了语法形态；`delivery` 自动判断状语；`episode.example.json` 重写成语法范本 |
| 中文名进了英文提示词；机检只说「有全角字符」不说在哪 | 缺陷 | 提示词不再用人名（见第二步）；机检给出上下文 |
| 开场站位把这一段里后进场的人也算进 `Exactly N people` | 缺陷 | `stagings` 增加 `enters_later`；空场开场也能写 |
| 参考图路径只认「相对分镜 JSON 所在目录」 | 缺陷 | 相对项目根目录也认 |
| 机检建议补的那句话，自己会被机检判成否定句 | 缺陷 | 改了建议与白名单 |
| 音色参考的保留关系写成画面用的 `attribute_transfer` | **错误**（脚本 + 文档 + 13 个类型包） | 官方给音频另立四个标记，音色参考用 `reference`；机检新增检查 |
| 文档说 API 工作流里参考输入是嵌套对象 | **错误**（文档） | 读 ComfyUI 源码（v0.37.2 与 v0.46.2 一致）：是带点的扁平键 `ref_images.ref_image_0`；写成列表或嵌套不报错、参考被静默丢掉。预检现在拒绝这两种写法 |
| `.media.json` 和 `comfy_submit.py` 之间没有衔接，要手工改工作流的提示词、帧数和接线 | 缺失 | `comfy_submit.py --media`：写入提示词与帧数、按顺序接参考，预览里打印接线表 |
| 提示词提到 `<Picture 5>` 而工作流只接了 3 张图，预检照样通过 | 缺陷 | 预检对账「提到的」与「接上的」 |
| `cues.srt` 只含本次构建的段，时间按请求秒数而不是帧格 | 缺陷 | 每次写全集、按帧格累计 |
| 几份文档之间规则互相矛盾（运镜修饰词、末镜景别、最短镜头时长、提示词字数） | 文档 | 各留一个口径，其余指过去 |

## 第二步：对照官方原文复核

修完之后，把脚本对示例分镜出的提示词和官方完整示例（`ref-en.txt` §7）并排读，又找出几处「格式对了、写法没对」：

| 差异 | 官方依据 | 现在 |
|------|----------|------|
| `[Shot 1]` 之前放了风格、场景、站位、承接状态三四句 | §5.2：`[Shot 1]` 之前只用一两句交代风格 | 只留一句风格；其余进 `[Shot 1]` |
| 定义和保留行里用人名（`<Subject 1> is Lin Lan, …`） | §2.1 与完整示例都不用名字 | `<Subject 1> is the woman in her early thirties in <Picture 1>, with …`；多张图写明各自提供什么 |
| 标签在镜头里出现时不带外貌 | §5.3：首次清楚出场处描述它的特征；完整示例在后续切镜写 `the young man in the dark-grey hoodie from Shot 1` | 脚本在首次清楚出场处插入外貌，之后切镜给该镜主体加短提醒；只露肩膀 / 手的镜头和别人的特写不算出场 |
| 台词结束后没有下文 | 完整示例每句台词后都跟 `She closes her lips and …` | `dialogue[].after_line`；不写则补一句闭嘴 |
| 音色参考只在该人第一句引用 | §5.3：在音频关系起作用的地方引用 | 每句都引用 |
| 三段式里用人名而首帧模式不写外貌，模型无从知道谁是谁 | `base-en.txt` 的示例用 `the young woman`、`the baker` | 用短称（`short_phrase`，默认取 `identity_phrase` 的开头） |
| `identity_phrase` 按生图的要求写了 30–45 词（骨相、族裔、身高），每段都整段进提示词 | 官方示例的特征只有发型 + 主服装 + 一个饰物 | 拆成两个字段：`identity_phrase`（进视频提示词，12–25 词）与 `sheet_phrase`（只给生图）；超过 30 词校验器会提醒 |
| 有台词的段末尾没有「只说引号里的词」这句（类型包的手写示例有，脚本没有） | 非官方写法；社区实测多说词 9.3% → 1.3%（`camera-and-performance.md` §5b） | 脚本在有台词的段末尾补 `Speak only the quoted dialogue lines.` |
| 7000 字符被当成硬上限，本地构建超了直接报错 | `comfy/text_encoders/minimax.py`：本地节点不限长度，7000 是云端 API 的限制 | 降为提示 |

顺带改的：`lint_prompt.py <提示词>` 自动读同名 `.media.json`（之前要手工给秒数和图片数）；测试 agent 写的分镜在 `action` 里每镜都重复外貌（`{xu_qing}, short black hair and beige trench coat, sits …`），现在校验器会提醒、`02-storyboard.md` 写明不要这样写；类型包里的 10 个六段式示例按同一版式重写（另一个 agent 改写，改完后逐个核对：台词、时间码、配乐与原文一致，没有残留人名，按各自文件写明的参数机检 0 错误）。

## 没有解决的 / 没有验证的

- **新写法没有在真实 H3 上做过对比。** 「首次出场带外貌、台词后闭嘴、定义不用人名」是照官方文档和示例对齐的，依据是「和训练时见到的写法一致」，不是实测结果。建议在用户机器上拿同一段、同一 seed，新旧提示词各出一次，看身份保持、口型和切点。
- 「清楚出场」是按 `framing` 的文字判断的（`over the shoulder of`、`the hands of` 这类说法算局部出镜）；写法偏了会放错位置——出提示词后读一遍。
- 人称代词按 `identity_phrase` 里的 woman / man 之类的词推断，推不出时用 their。
- 模拟服务只模拟 HTTP 接口：`--media` 的接线在真实 ComfyUI 0.37.2 上没有跑过。
