# 迭代 12：装机与规划第三次复测（2026-11-23）

这一次复测的 agent 多了一样东西：一台真实的 ComfyUI 0.37.2（装了 KJNodes、ResCascade、LBH 节点，模型文件按真实文件名放着空的占位文件，没有显卡）。它仍然没有上下文，只读 skill 的文档，按用户的条件（Windows 11、RTX 4090、ComfyUI 0.37.2 便携版、只能走 HuggingFace / GitHub、手里没有素材）把流程从装机走到成片；能在这台机器上跑的命令都实际跑了（135 次工具调用，命令和输出都留了日志）。

## 结论

- **第一批草稿：部分可以，接近可以。** 下载清单是对的（14 个文件在 HuggingFace 上都在、不需要申请、大小误差 0.1 GB 以内）；附带的 11 个工作流在各种用法下都被真实服务器接受；清单第 4 项「预检附带的草稿工作流」和文档写的一字不差。要猜的地方很小。
- **30 秒成片：部分可以。** 后期链路在合成片段上从 QC 到混音、导出一次走通；剩下的是精修没有实跑、音色锚点依赖一条分镜提示词里没写的规则、出图环节没有把关、时间给不出承诺。

上两次的结论分别是「不行」和「部分可以」。

## 发现和处理

| 发现 | 性质 | 处理 |
|------|------|------|
| 清单第 3 项「官方模板原样跑一次」跑不起来：模板开关里挂的 4 步 LoRA 不在下载清单里（关着开关 ComfyUI 也校验它），两张示例图也不会自己出现 | 文档与事实不符 | 改成用附带工作流的冒烟测试：新增 `assets/workflows/smoke_test_prompt.txt`（5 s、纯文字），配 `h3_ref2va.api.json` 不用任何素材就能确认 H3 出片；真实节点上验证过参考节点不接参考也能跑。官方模板的额外要求写在旁边 |
| 出图是「盲发」的：预览只有模型和采样器；空提示词、拼错的 `--set` 输入名（`459:452.text`）、忘了给的第二张图（悄悄用了 ComfyUI 的 example.png）都显示 `preflight ok` 并被服务器接受 | 脚本缺陷 | 预检拦下：正向提示词为空、图片位还是 `(not set)`、`--set` 写了节点没有的输入名（列出真正的输入名）；出图预览列出尺寸、每张输入图、提示词开头 |
| 流程是串行的：每个后续段都要等上一段选片、观测，再回去出首帧，再出视频——一集里出图模型和视频模型来回换四次 | 流程代价 | 改成默认「先批量、后对账」：首帧按计划的末态一次做完，`build_prompts.py --allow-planned` 一次出全部提示词，草稿一次抽完；选片时结尾和计划一样就 `observe_take.py --as-planned`，再建一次提示词——下一段标 `[unchanged]` 草稿照用，标 `[CHANGED]` 才重做 |
| 精修只有一条没实跑过的路，文档里的备用方案（分块）没有工作流 | 文档缺失 | 写明二采跑不下来就先用草稿装配（`mix_episode.py` 会缩放到 1920×1080，复测里实际走通）；另外已有 `--keep-latent` / `--from-latent`（迭代 11） |
| 没有音色样本的用户：按 3.3–4 字/s，8–10 字的第一句只能截出 2–3 s 的样本；「每个主角第一句 ≥ 12 字」只写在音频文档里；1.0 s 的样本一路通过 | 文档缺失 + 脚本缺口 | 校验器提醒：没有样本的角色在第一次开口的那段里最长一句不足 12 字；样本不在 2–15 s；已有采纳片段却还没截样本。分镜提示词模板加了这条规则。提交预览在每个音色后面标出秒数 |
| 同一个工作流关掉 Turbo 出 20 步时，估时用的是 8 步的历史 | 脚本缺陷 | 估时只用同步数的历史；只有别的步数时按步数折算并注明 |
| `run.json` 里的耗时是从提交算起的墙上时间（轮询间隔、排队、续取都算进去了） | 文档与工具不符 | 耗时改取服务器历史记录里的起止时间戳，墙上时间另记 |
| 分镜表显示「3.3 字/s，上限 3」而节奏检查不报 | 文档与工具不符 | 两处改用同一个数：本镜约可容多少字（能说话的秒数 × 3 + 1），超了才标 |
| lint 对生成器自己写出的 314 词的第一镜告警，却没说能改哪里 | 提示不可操作 | 告警写明可以缩短的是分镜里的 action / 表演、continuity、identity_phrase |
| 真人对白段没有首帧时不提醒（铁律 17） | 脚本缺口 | 校验器提醒 |
| `catalog.py` 给 `prop_watch.png` 生成 `prop_prop_watch` | 脚本缺陷 | 已有前缀时不再重复加 |
| 9 处互相矛盾的说法（视频 VAE 的大小、出图步数 50 / 20 对附带工作流的 25 / 40、首帧用 bust 还是 face.png、2 个还是 3 个 seed、30 s 是 3 段还是 4 段、指错的章节号等） | 文档矛盾 | 逐条改掉 |
| 把 `no other item is substituted`、`never transfer facial traits` 称作「官方保留句式」，官方指南里查无此句 | 错误陈述 | 改为「本流程固定使用、lint 放行的句式，不是官方原文」 |

## 它确认可用的

自检 43 项、连通测试、预检、11 个工作流的全部用法（含 `--anchor`、两条音色、精修、i2va）、已完成跳过、旧结果归档、中断后续取、过期的 `--confirm` 被拒绝；分镜校验 → 渲染 → 生成提示词 → lint 一次通过；合成片段上的 QC、联络表、观测、逐段重建、音色样本裁切、剪辑单、字幕、混音（四项验收全过）、音色检查、OTIO 与剪映导出。skill 文件夹在测试前后哈希一致。
