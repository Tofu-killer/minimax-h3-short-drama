# 迭代 11：用真实权重和真实节点能验证到哪一步（2026-11-23）

迭代 10 装起了一台真实的 ComfyUI 0.37.2，但模型文件是空的占位文件，只能验证「服务器接受这个工作流」。这一轮往前再走一步：没有显卡、装不下 33B 的底模和 32B 的文本编码器，但流程里不需要这两样的部分其实不少——把它们用真实权重实际跑一遍，把只能靠读源码的结论换成跑出来的结果。

## 做法

1. **只读文件头部**：HuggingFace 上的 safetensors 文件，用 Range 请求只取开头的张量名、形状和元数据（几十 KB），不下载几十 GB 的权重。拿它对照 ComfyUI 0.37.2 自己的识别代码和 LoRA 加载代码。
2. **第二个实例 + 小权重**：另起一个 0.37.2 实例，下载真实的 H3 视频 VAE（int8，2.8 GB）、H3 音频 VAE（0.6 GB）、LBH 放大器（0.7 GB）、Qwen-Image VAE（0.25 GB），在 CPU 上以小尺寸执行。
3. **替身文本编码器**：H3 的条件节点只调用文本编码器的两个方法。写一个只返回空条件的替身节点，H3 的参考节点、首尾帧节点、关键帧节点就能带着真实的 VAE 实际执行，再把它们产出的条件内容写出来看。

## 真实权重跑出来的

| 跑了什么 | 结果 |
|----------|------|
| H3 的空音画 latent → `VAEDecode` + `VAEDecodeAudio` → `CreateVideo(24)` → `SaveVideo` | 24 fps，帧数 = `length`；音频 32 kHz 立体声，与视频等长 |
| latent 的形状 | 视频 `[1, 24, 5k+2, 高/16, 宽/16]`（帧数 17k+5）；音频 `[1, 32, 2, 40 × 秒数]`。由此得到 token 公式，写进了参考文档 |
| `SaveLatent` 直接接 H3 的合并 latent | 报 `'NestedTensor' object has no attribute 'contiguous'`，和文档说的一致 |
| 拆分 → 两个 `SaveLatent` → 取回 → 传回 → 两个 `LoadLatent` → 拼回 → 解码 | 通。据此给 `comfy_submit.py` 加了 `--keep-latent` / `--from-latent`：精修可以直接从草稿存下的 latent 开始，一采不重跑 |
| LBH 放大器（经 ResCascade 的节点） | 448×256 的 latent → 640×352，音频 latent 原样带着 |
| 16 kHz 单声道 6 s 的音色样本过 H3 音频 VAE | latent `[1, 32, 2, 240]`，解码回来 32 kHz 立体声 6 s |
| 1344×768 的空潜空间过 Qwen-Image VAE | 解码出来 1344×768（编辑出图工作流的固定画布） |
| `FluxKontextImageScale` 对几种尺寸 | 1344×768 → 1328×800、1920×1080 → 1392×752、1024×1536 → 832×1248，和文档里按源码算的一致 |
| 真实前端打开附带的 API 格式文件 | 节点全部认得，可以拖进界面查看和修改 |

## 真实节点（替身文本编码器 + 真实 VAE）跑出来的

用脚本为一个带首帧、第二镜关键帧、脸、全身、场景、道具、音色的段接好的工作流：

- 7 个参考到达节点的顺序，和提示词里的 `<Picture 1…6>`、`<Audio 1>` 一一对应。
- `ref_image_size = match`：1024×1024 的脸保持原样，1024×1536 的全身成了 832×1248，2688×1536 的场景、1920×1080 的关键帧都成了 1344×768，2048×2048 的道具成了 1024×1024——每张约 1,000 个 token，和原图大小无关。（文档里原来引用别人的「2 张 ≈ 1,550」，已换成实测。）
- `--anchor` 接出的两个 `MiniMaxH3AddGuide` 执行通过，条件里得到第 0 帧和第 96 帧两条关键帧。
- `MiniMaxH3ImageToVideo`：同一张带白条的正方形图当首帧和尾帧，首帧里白条仍占 1/3（整张被压扁），尾帧里只剩 0.208（居中裁切）——「首帧要按画布比例出图」这条规则有了实测依据。

## 仍然没有验证的

文本编码和采样，以及由它们决定的一切：画面、口型、耗时、显存、`H3 Hires Fix` 的二采效果、Sage 节点的实际加速。这些只能在用户的 4090 上确认，顺序见 `assets/first-run-checklist.md`。
