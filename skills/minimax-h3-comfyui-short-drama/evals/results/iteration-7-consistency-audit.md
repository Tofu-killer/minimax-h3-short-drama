# 迭代 7：全量一致性审计（2026-11-21）

前三轮可用性测试各自只读了完成任务要用到的文件，却都撞上「两处文档说法不一」。这一轮请一个 agent 只读地把整个 skill 过一遍——`SKILL.md`、15 份 reference、风格包、类型包的说明文字、模板、schema、示例和全部脚本——专找四类问题：同一个量在两处给了不同的数、文档里写了但脚本里没有的参数 / 字段 / 文件、文档描述的行为脚本已经不是这样、同一条规则一处写必须一处写不要。裁决顺序：脚本的实际行为 → schema → `storyboard-and-assets.md` §1。

它读完 61 个文件，报回 35 条主要发现和 20 条小项。它同时确认：文档里出现的每一个命令行参数都存在；每一个 skill 内部的文件路径都存在；质检与后期文档里引用的阈值与脚本里的常量一致；`prompt-format.md` §3 的样例与构建器输出一致。

## 脚本缺陷（由代码裁决）

| 发现 | 后果 | 修复 |
|------|------|------|
| `qc_probe.py` 拿「请求秒数」去比片段时长，没按 17k+5 帧格换算 | 13 s 的段实际生成 13.667 s，差 0.667 s > 容差 0.6 s——**每一条正常生成的 13 s 片段都被判 FAIL**；6 s 的段只差 0.017 s 没过线。自检用的是整秒合成片段，所以一直没暴露 | 期望时长改为帧格上的长度；自检新增一项「校验器、机检、质检三处的帧格换算必须一致」 |
| `identity_gate.py` 只认「相对分镜 JSON 所在目录」的参考图路径，而文档和 schema 都说相对项目根目录也可以 | 按文档写路径时所有参考图都报缺失、整个门禁退出 | 与其它脚本用同一条规则 |
| 文档里的 `contact_sheet.py "takes/ep01/s03/*.mp4"` 匹配不到任何文件 | `comfy_submit.py` 把每个候选放在自己的子文件夹里 | 文档和脚本说明都改成 `**/*.mp4` |
| `lint_prompt.py` 对 10 s 以上的段建议 3–5 镜，而校验器和 schema 的上限是 4；对白段按规则可以少一镜却被警告 | 合规的分镜收到机检警告 | 上限改 4；有台词的段下限减一 |
| 打斗「每击一镜 0.8–1.4 s」被写成例外，机检却对任何短于 1.2 s 的镜头报错 | 照文档写会过不了机检 | 三处文档改成「每击一镜，但每镜写 1.2–1.6 s，更碎的切点后期剪」 |
| `--bilingual` 依赖台词的 `en` 字段，schema 和字段表里都没有 | 用户不知道英文字幕往哪填 | schema、数据模型、字段表补上 |

## 文档对脚本说了不存在或已经变了的事

- 资产表说场景「两张都接」、还列了「主角板 / 道具拼板 / 动作参考视频」的取材优先级——构建器每个场景、每个道具只接第一张，不接视频。改成脚本真实的接法。
- 续接参考里的接缝处理（4 帧叠化、40 ms 交叉、自己写 concat 脚本）在 skill 的装配脚本里不存在，也与铁律 19 相悖。改成指向 `mix_episode.py`。
- 1344×768 交付 1080p：一处写「横向拉伸 1.6%」，脚本和其余文档都是裁切。统一为裁切。
- `takes.csv` 没有显存列；国际版 CapCut 导出要另装 `pycapcut`；不存在的章节号（§5b）；`frames_ok` 这个字段并不存在；几处指向不随 skill 安装的文件。逐条改了。

## 文档之间互相矛盾（脚本不裁决，选定一种说法）

| 主题 | 原来的几种说法 | 定为 |
|------|----------------|------|
| 多人画面的首帧 | 四处写「多人只给首帧 → i2va」，类型包 01 却是双人对白用 ref2va + 首帧 + 两人参考 | 首帧里只有一张清楚的脸（单人、过肩）→ ref2va + 首帧 + 参考 + 音色；两张以上清楚的正脸 → 只给首帧（i2va，接不了音色参考） |
| 「同 seed 精修不改构图」 | 精修有三种定义，其中两种（换步数关 Turbo、换分辨率重跑）其实会出一条新片段 | 只有 latent 二采保住原片段；其余算新片段，要重新选片、重新观测 |
| 角色参考 | 八个类型包仍写「准备角色设定板当参考」，另四处写设定板只给人审 | 一律单人单视图（face.png + 正面全身）；槽位不够时每人一张，不退回设定板 |
| 风格包里的生图模板 | 含 `photorealistic, 4K`、`no people`、多视图并排——都是生图规则禁止的写法 | 删掉，指向 `image-prompts.md` |
| 每段几个 seed | 2–4 / 2（关键镜 3）/ 2–3 | 2–3，有台词的段 3 个 |
| 重抽上限 | 五种说法，其中三种在同一份文件里 | 同一个问题连续两批都在就改提示词或分镜；偶发技术故障原样重试一次（铁律 10） |
| 何时离开 H3 | 两处「且」、一处「或」，「两批」与「三次」 | 命中路由表的镜头类型，且改过之后仍连续两批不过 |
| 尾帧接力用什么模式 | I2VA / FL2VA / ref2va + first_frame | 默认硬切；例外才用尾帧作 `first_frame`（ref2va，同时带角色参考） |
| 连续静态对白段 | 文档「禁止连续两段」，校验器第三段才报错 | 连续两段尽量避免，三段报错 |
| 参考图尺寸 | 目标画幅短边 768 / 方形或竖幅短边 1024 | 短边 1024，角色图不必是目标画幅 |
| 段长、镜头数的残留 | SKILL 铁律 13 的 5–12 s、类型包里的 12–15 s、5–10 s 等 | 全部改到 §1 的数；§1 写明「对白段少一档」数的是有台词的镜头 |

另有十来处小的：加速文档里合并 LoRA 与否、kitchen 注意力旁路与启动参数、DMAD 4 步的适用范围、接线骨架少一个 Sage 节点、生态表把有损的稀疏注意力列在「采用」、NVFP4 的适用范围、音色样本长度、三处锁音频配方的节点名、像素超分表里 SeedVR2 的评价、示例剪辑单里一处与 `end_hold` 不符的帧号、盘点清单缺的几项（注意力 / 缓存节点、SigmaShift、驱动、CUDA 系统内存回退）。
