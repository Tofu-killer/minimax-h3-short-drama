# 迭代 6：创作链路复测（2026-11-21）

迭代 5 把提示词构建器按官方示例重写之后，再请一个没有上下文的 agent 用一段新剧本（《最后一班渡船》：两个主角、一个没有参考图的路人、两个场景、一件关键道具）把创作链路走一遍，并让它把脚本出的六段式提示词逐条对着官方指南原文挑出入。它只读 `SKILL.md` 及其指到的文件；ComfyUI 用模拟服务代替；「采纳的片段」用现成素材顶替。

**结果**：链路走通（3 段分镜、三段提示词机检 0 错 0 警告、两次批次预览、一次实拍末态交接）。它的结论是「能做完，但不猜做不完」，报回 19 类问题和 25 处与官方指南的出入。下面按它排的代价高低归并。

## 代价最高的三个

| 问题 | 性质 | 修复 |
|------|------|------|
| **段间交接**：上一段的结束状态写的是全屋（按文档要求），其中提到的人下一段没绑定——校验器和分镜表都放行，直到采纳了片段、`observe_take.py --write` 才报错，报错建议的 `--allow-planned` 也失败；最后只能把不出场的人绑进下一段 | 脚本缺陷 | 状态（`continuity` / `end_state` / 实拍末态）可以提到本集任何资产，下一段没绑定的用文字称呼；`observe_take.py` 不再拒绝，只提示 |
| **状态用的是上一个机位的画面坐标**（`at frame centre`），被原样贴进下一段换了机位的首镜；结束状态还会写进脸部特写镜头，描述镜头里拍不到的东西 | 设计缺陷（与官方 §5.3「只写镜头里看得见的」相左） | 状态改写人在**房间里**的位置（靠着什么、在谁的左右、面朝谁）；`observe_take.py` 的提示语、分镜模板、校验器（提醒画面坐标）同步；结束状态只在末镜是中景或更宽时进提示词；句式改成描述句 `As the video opens, …` / `At the end of the video, …` |
| **分镜规则散在四份文档里、数字互相不同**（对白镜最短 3 s / 4 s / 2.5 s，镜头数 2–4 / 3–5，爆点段 13 s / 15 s，语速四种说法……），流程表只指向其中一份；工具只查其中一小部分 | 文档矛盾 | `storyboard-and-assets.md` §1 定为唯一口径，其余文件改成引用或注明是别人的更保守做法；`02-storyboard.md` 补全运镜词表、转身次数、说话动词等此前只在别处出现的规则；校验器新增「有台词的镜头 < 3 s」「action 里出现 speaks / says」，机检新增非官方的运镜修饰词 |

## 其它脚本问题

| 发现 | 修复 |
|------|------|
| 流程表第 5 步的命令缺 `--out`，照抄即报错 | `--out` / `--tag` 由 `--media` 推出 |
| 预览里的「预计多久」把 8 s 片段的耗时原样套到 12 s 片段上 | 按帧数 × 画布折算；`run.json` 与 `takes.csv` 记帧数和设置摘要 |
| 工作流没接 VAE、8 步却没有蒸馏 LoRA，预检照样报 ok | 预览新增 advice 行：参考节点没接 `vae` / `audio_vae`（节点自己的说明：不接则参考只进文本编码器）、步数与 LoRA 不配、cfg ≠ 1、画布比例与分镜画幅不一致 |
| 没有参考图的路人：校验器的提示说「只会被称作 the ticket clerk」，实际构建器写出 `the ticket clerk, a ticket clerk, sits …` | 同义重复时不再加同位语；路人不要求特征列表；文档写明路人怎么建 |
| 保留行写 `appears in [Shot 1], [Shot 2]`，正文里 `[Shot 3]` 也用了这个标签 | 出场镜头从写好的正文里读 |
| `build_prompts.py` 在「下一段等上一段选片」这个正常状态下退出码为 1 | 单列为 WAITING，不算失败 |
| 7 个参考（5 图 + 2 音色）没有任何提醒 | 校验器把音色也计入，> 6 提醒 |
| `--rhythm` 没有发现时什么都不打印；分镜表把没有图的人列在「参考」下 | 打印 `rhythm check: no findings`；分镜表标「无图，只有文字」 |

## 与官方指南的出入（它列了 25 处）

- **改了的**：风格句从「硬塞进一句话的逗号列表」改成 `The target video is in the following style: …`；`[Shot 1]` 改成完整句 `The video opens on …`；外貌按阅读顺序跟在首次提及之后，中景及更宽的镜头里在场的人都算出场；`(S1)` 也跟在景别句里的说话人标签后面；有音色参考时同时写嗓音的文字描述；道具定义不再把名字说两遍；人物保留行的「场景取自」改成场景的标签；summary 里的音色句改成官方句式；声音句紧跟它对应的动作；全文统一叫 `the video`、拼写用美式；示例和模板要求 action 里不写 speaks（之前示例自己就写了）。
- **有意保留的**：结束前的定格句、`Speak only the quoted dialogue lines.`（拼接和防多说词需要）；场景写 `partially_preserved`（写 fully 会把参考图的机位一起锁住）；每镜都写运镜句；`detailed_description` 比官方「通常 350–500 词」略长。
- **查过、不用改的**：`<d>` 里的中文全角标点。官方只有英文版指南（仓库里没有中文版）；基础指南 §4.4 的规则是「原样保留用户给的每个字和标点」，参考指南里「标点规范成 , . ? !」说的是从参考音频转写出来的台词。剧本台词照原样写。

## 文档

除上面的口径统一外：16:9 画布怎么选（默认 1344×768 生成、交付时裁 6 px 再缩放）、类型包与风格句怎么叠、`identity_phrase` 在素材不足时不凑数、`project.yaml` 给出模板并说明没有脚本读它、资产表存在哪、「采纳的片段」指哪个文件、`takes.csv` 实际记了什么、草稿档步数与分辨率的几处不同说法、节点名 `PathchSageAttentionKJ` 的拼写、示例分镜改成示范 `"@observed"` 交接。

## 没有解决的 / 没有验证的

- advice 行只认得出文件名里带 turbo / pdd / lightx2v / distill / step 的 LoRA；别的蒸馏 LoRA 会被当成没有。
