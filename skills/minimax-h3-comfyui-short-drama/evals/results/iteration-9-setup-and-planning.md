# 迭代 9：装机与生图规划测试（2026-11-21）

前几轮都是从「ComfyUI 已经能跑、素材已经有了」开始的，开头那一段没人走过。这一轮请一个没有上下文的 agent 按用户的真实条件——Windows 11、RTX 4090 24 GB、ComfyUI 0.37.2 便携版、只能从 HuggingFace / GitHub 下载、手里没有任何素材——只读 skill 的文档，排出一份能照做的方案：查环境、还要下载和安装什么、草稿与精修怎么配、图按什么顺序出、第一批提交什么。它不联网，除了 `--help` 不运行脚本。

**结论：不行。** 配置数值都查得到，不用猜（画布、步数、LoRA 与强度、shift、哪些加速不能叠、出图模型的文件名、分段的算法、确认关卡）；但从这些数值到「一个能跑的环境 + 第一批草稿」之间要猜三处：工具怎么装怎么接、这个题材的首帧怎么设计、要花多久和成片走哪条路。共 32 条发现。

## 代价最高的

| 问题 | 性质 | 修复 |
|------|------|------|
| **`--batch` 在官方模板的采样链上不能用**：脚本只认字面值 `seed`，而官方模板出噪声的节点叫 `RandomNoise`、输入名是 `noise_seed`；预览里的步数也只认 KSampler。照文档提交第一批会直接退出 | 脚本缺陷（对着 ComfyUI 0.37.2 源码确认） | `seed` 和 `noise_seed` 都认；预览能读 `BasicScheduler` / `KSamplerSelect` / `CFGGuider`，接在原始值节点上的数读得出来，由开关或公式算出来的写明「在工作流里计算」 |
| **从官方模板到脚本能用的工作流没有桥**：模板叫什么、要改哪几处、Ref2VA 和 FL2VA 是不是各要一份、音频怎么解码，都没写 | 文档缺失 | `comfyui-nodes.md` §2 换成逐个读模板 JSON 得到的默认值，§3 写成 7 步改法；说明脚本怎么认种子、提示词、参考和预览 |
| **Windows 便携版上装什么、装到哪**：脚本用哪个 Python、可选依赖装哪、ffmpeg 从哪来、KJNodes 是哪个仓库、Sage 怎么装 | 文档缺失 / 有名字没来源 | `local-stack-and-acceleration.md` §0b：另装 Python（不动 `python_embeded`）、ffmpeg 两个来源、KJNodes 仓库、SageAttention 的两条路（Windows 预编译包，或启动参数 `--use-ck-attention`）——仓库、文件名、版本规则逐个核对过 |
| **草稿分辨率和时间目标对不上**：默认画布 1344×768 的耗时是外推的 5–8 min，文档却写「速度有实测」、草稿目标又写 ≤ 2–3 min；544p 档的 Turbo LoRA 没有文件名 | 文档互相矛盾 | 草稿分成两档并写清各自用途（快速预览 / 同构图草稿）；实测和外推分开标；核对 HF 文件清单：Ref2V **没有** 8 步的 544p 版 LoRA，官方 r2v 模板默认挂的是 4 步 544p 档 |
| **这个题材的首帧怎么做**：两个人 + 场景已经占满编辑模型的三个输入，道具放不进去；道具特写（画面里没有脸）用哪种模式有三个答案；先做下一段的首帧还是先观测上一段没有顺序 | 文档缺失 / 互相矛盾 | 道具入画尽量设计成单人镜，两人加道具分两步编辑；没有脸的道具特写 → `ref2va` 挂道具参考；接着演的段等上一段观测完再做首帧 |
| **一段要带 9 个参考**（首帧 + 两人各两张 + 场景 + 道具 + 两段音色），而文档说 ≤ 6 最稳；角色带几张图只能按角色定，不能按段定 | 设计缺口 | 新字段 `character_refs`（这一段里每个角色带几张图，0 = 不带、改用文字称呼）；参考超过 6 个时校验器提醒 |
| **手里没有音色样本怎么起步** | 文档缺失 | 三条路按可靠程度排：自己录 6–8 s；第一段先不挂音色出片，从选中的片段里截这个角色的声音当锚点（给了 ffmpeg 命令）；TTS 造声线（没实跑过，如实标注） |

## 修复时自己查出来的

把准备写进文档的每条事实对着 ComfyUI 源码、模板 JSON 和 HF 文件清单又核了一遍，查出几处测试报告里没有、但照做会出错的：

| 发现 | 依据 | 处理 |
|------|------|------|
| **官方 Edit 2511 模板出不了 16:9**：出图尺寸跟着第 1 张图走，而且会被缩到一张固定尺寸表里比例最近的一项——1344×768 进去变 1328×800，1920×1080 进去变 1392×752 | 模板 JSON 的连线 + 0.37.2 `nodes_flux.py` 的尺寸表逐项算 | `image-stage.md` 写明：做逐镜首帧时换成 1344×768 的空潜空间 |
| **`i2va` 的首帧会被直接拉伸到画布，不裁切**；尾帧才是居中裁切。上一条的两个尺寸进去，脸会变宽 5.4% 或变窄 5.5% | 0.37.2 `nodes_minimax_h3.py`：`first_frame` 用 `crop="disabled"` | 文档写明首帧要按画布比例出；`comfy_submit.py` 的预览在首帧 / 尾帧和画布比例差超过 1% 时提醒（直接读 PNG / JPEG / WebP 文件头，不需要图像库） |
| **官方 Edit 模板的默认值是 40 步 CFG 4**。节点上残留的数字是 CFG 3，真正生效的值是从开关接进来的——第一遍我照残留数字写成了 CFG 3，重读连线后改正 | 逐条追模板 JSON 里采样器的输入连线 | 文档里的模板默认值都改成「读连线得到的」，并注明 |
| 官方 Qwen-Image 2.1 模板里有一条默认关闭的提示词扩写支路，它要的 9.5 GB 模型文件不在 skill 的下载清单里；开关关着也会被 ComfyUI 校验，缺文件就拒绝提交 | 0.37.2 `execution.py`：校验沿所有连线走 | 写明两种解法：下载它，或删掉那条支路 |
| **ComfyUI 自带的 `SaveLatent` 存不了 H3 的 latent**：H3 的 latent 是视频和音频两个张量合在一起的，`SaveLatent` 对它调的方法在这种对象上不存在 | 0.37.2 `nodes.py` + `comfy/nested_tensor.py` | 精修的默认做法改成「同 seed、同设置重跑一采，再接放大」；想存 latent 的要先用自带节点拆开，写了步骤 |
| **文档里精修节点 `H3 Hires Fix` 的接法已经过时**：写的是前面先拆 latent、后面再接采样器、参考条件要在新尺寸重建；当前版本直接吃音画合并的 latent、在节点内部完成采样、Ref2VA 的参考原样沿用、首尾帧关键帧自动丢掉 | 2026-11-21 读该仓库 main 分支的 `hires.py` 和 README | `quality-pipeline.md` §4 按源码重写：接线、三种模型 / 步数配法、作者主张（一采用原生 20 步）和本流程（一采是 Turbo 草稿）的差别 |
| 精修如果用同一个 seed、同一个 `--tag` 提交，结果会落进中选草稿的目录，草稿被挪进 `_prev_…`，之前记下的片段路径失效 | 读脚本 + 在模拟服务上复现 | 预览里对这种情况提醒并建议另起 `--tag`；文档的精修命令带上 `--tag <段号>_refine` |
| `build_prompts.py` 遇到分镜里写了、磁盘上没有的参考文件，会抛一长串 Python 回溯 | 回归时撞到 | 改成一行说明，其它段照常生成 |
| `SKILL.md` 头部的 compatibility 字段这一轮被我加到 566 字，超过安装器 500 字的上限，打包会被拒 | 打包器的校验规则 | 缩到 473 字；自检新增一项检查头部长度 |
| 示例分镜引用的全身图叫 `lin_lan_outfit.png`，和文档约定的 `<id>_full.png` 不一致 | 测试 B29 | 文件和引用都改名；文档说明示例里的图是占位文件、没填首帧只是为了不带素材也能跑通 |

## 其它已修的

- 「先跑一次基线」指的是什么：int8 底模 + Turbo 8 步 + Sage、别的加速全关，一段固定的 10 s 提示词。
- 采样器、VAE、LoRA 合并方式几处「两种说法」统一；「合并还是运行时挂载」写明是哪两个社区节点的开关，用官方模板的加载节点时不存在这个选择。
- 流程顺序改成实际顺序：大纲 → 生图 → 看着图写外貌短语 → 分镜 → 首帧。
- 场景参考接的是无人母版；九宫格带格线和数字，只用来裁图和给人对照。
- 首帧模板里写死的胶片 / 镜头描述要换成和分镜 `style` 一致的说法。
- 帧数对照表补全到 5–13 s，说明三段 10 s 交付出来约 27 s、要 30 s 得用 11 / 11 / 10。
- 二采工具的来源补全（ResCascade、LBH 放大器、DMAD LoRA 各在哪个仓库；拆分 / 合并 latent 的节点是 ComfyUI 自带的）；8–13 s 对白段先整段二采、爆显存再换分块。
- 出图也能用 `comfy_submit.py` 排队并出批次预览；裁母版、几张静帧并排审各给了一条跑过的 ffmpeg 命令。
- 出图模型怎么选写成一句话：不营利用 Qwen-Image 2.1，要营利用 Z-Image-Turbo。
- 可选依赖补上 `numpy`，注明语音识别模型首次运行时从 HuggingFace 下载。
