# 迭代 14：在微型模型上从装机做到成片的第五次独立测试（2026-11-23）

第五次请一个没有上下文的 agent 只凭打包后的 skill 做一遍，这次它手里有一台能真正出片的服务器：真实的 ComfyUI 0.37.2 + 上一轮造的微型随机权重 H3（真实的 VAE 和 LBH 放大器）。任务是两段各 5 秒的迷你集，从环境检查做到 1920×1080 的成片，中途故意犯七种常见的错，H3 任务上限 10 个。它用了 9 个，跑了 185 次工具调用，留下 160 多份日志。

画面是噪声（权重是随机的），所以这一轮验证的仍然是**流程和工具**：每一步有没有写清楚、出了岔子脚本说不说、说得对不对。画面、口型、耗时、显存照旧要在 4090 上验。

## 结论

| 问 | 答 |
|----|----|
| 只凭 skill 能不能做出第一批草稿 | **能**。环境检查、连通性测试、冒烟测试、分镜、提示词、预览确认后的批次，都照文档走通；出图阶段在这台机器上只能预览（11 条命令全部通过预检） |
| 能不能做到成片 | **部分能**。链路走到了一个通过自身验收的 1920×1080 成片；但没有任何东西把剪辑和「采纳的片段」绑在一起，另外三种常见情况（重做首帧、挂音色、`--stale-ok` 采纳的片段怎么精修）文档没有交代清楚 |

它确认不用猜就能做的：自检、连通性与冒烟测试、模型核对、出图清单、每一条预检信息、批次预览与 `--confirm`、相同的片段自动跳过、中断后接回原任务、`--keep-latent` / `--from-latent`、同 seed 重跑与保留的 latent 在 CPU 上逐字节一致、精修后的声音与草稿一致（相关系数 0.996）、技术 QC、台词 QC、剪辑单、字幕、混音（196 帧、−14.0 LUFS）、OTIO 和剪映导出。

## 七种故意犯的错

| 错 | 脚本的反应 | 够不够 |
|----|-----------|--------|
| 把别的段的片段拿来采纳 | 退出码 1，「is not a take of s01: it was made for segment s02 … Nothing was written.」 | 够 |
| 上一段结尾变了，再采纳按旧提示词抽的草稿 | 拒收，给出「重抽」或「看过接得上再 `--stale-ok`」两条路 | 够；但**怎么重做首帧**没说 |
| 后一段已采纳，前一段又换了结尾 | `CHECK THE CUT`，校验器持续提醒，确认后提醒消失 | 够 |
| 草稿抽完才挂音色样本 | 提示词标 `[CHANGED]`、草稿列为过期、拒收；**没说是音色造成的** | 一半 |
| 提示词文件忘了写 `@` | 退出码 2，给出正确写法 | 够 |
| 尺寸写成 `1344x768` | 退出码 2，给出两个数分开写的写法 | 够 |
| 精修时换了设置 | `--seed` 路线逐项指出；**`--from-latent` 路线只比提示词和参考**，换画布、关 Turbo 都不出声 | `--from-latent` 不够 |

## 它列出的缺口和这一轮的处理

| 缺口 | 处理 |
|------|------|
| 剪辑单和混音收任何片段：没采纳的那条、过期的草稿都能一路做成成片，一个字不说 | `make_edl.py` 把每段的片段和分镜里记的采纳片段对一遍。是它本身、它的精修（同提示词、同参考、同 seed）或这两者的副本（按内容在该段的片段文件夹里找回出处）不出声；别的 seed、按别的提示词抽的、没采纳过的段 `WARN`，末尾汇总 `CHECK:`。警告存进剪辑单，`mix_episode.py` 验收时再报一次；重跑时保留下来的条目也重新核对 |
| `--stale-ok` 采纳的片段：脚本说「从它存下的 latent 精修」，精修预览却警告「提示词和参考变了」，而旧的提示词哪儿都没留 | 每条片段的文件夹里现在留着它当时的提示词（`prompt.txt`，逐字节）和参考清单（`media.json`，指向旁边的 `prompt.txt`）。这种片段精修时用 `--media <片段文件夹>/media.json`；几处提示都改成了这句。在微型模型上实际执行过：草稿 → 用它自己的 `media.json` 加 `--from-latent` 精修，预览写「same prompt and references, same canvas, same length」，出片 640×352、39 帧、带声音 |
| `--from-latent` 只比提示词和参考 | 现在还比 H3 节点上的画布（参考图和钉住的帧是按节点上的尺寸准备的）和帧数，不一致就警告并给出要补的 `--set`。Sage 和 Turbo 开关不比——一采不重跑，它们只影响二采，文档里写明了 |
| 预览尺寸的片段可以被采纳、再被精修，而文档说不行 | `observe_take.py` 不收比草稿画布小的片段（确实按这个尺寸做才加 `--small-ok`）；二采放大超过 1.75 倍时预览给一条 advice |
| 重做首帧：出图清单说「0 张要做」，旧的提示词文件原样留着 | `plan_stills.py` 记下它写过什么、每张图是按哪份提示词出的。分镜里的出图提示词改了，再跑一次它会重写提示词文件，并把盘上那张图标成 `MAKE AGAIN`；手改过的提示词文件不动（分镜后来又变了才提醒一句） |
| 挂音色的先后没写「先采纳」 | SKILL.md 第 2、5 步和 `audio-and-post.md` 写明：先 `observe_take.py` 采纳，再截样本写 `voice_reference`。拒收过期草稿时现在说明变的是什么——提示词、哪张图内容变了、后来挂上的音色样本 |
| 每个角色只在一段里说话时没有任何提示 | `build_prompts.py` 加一条 note：这种样本这一集用不上，要截也先采纳 |
| 第 3 步的校验在首帧做出来之前过不了（退出码 1） | 分镜点了名但还不在盘上的图 / 音色改为以 `+` 列出，不算错误；分镜本身没问题就是 `OK` |
| 节奏检查说「约可容 11 字」，分镜表说「约可容 12 字」，同一个镜头 | 两边都改成按实际帧数算末镜的长度（5 s 的段实际是 5.167 s），现在是同一个数 |
| 5 秒的对白段：12 个字被说成「会说得太赶」，11 个字被说成「不够截音色样本」 | 上一条修掉之后这个例子不再矛盾；音色样本的提醒另外改成看镜头放得下多少字——放不下 12 字时改为建议把两句接成样本 |
| 节奏检查说 5 秒两镜一句「过载」，而分镜规则的表允许 | 节奏检查改成按那张表查；「拍数」（镜头数 + 台词句数）的阈值从每拍 2 s 降到 1.5 s（表里最密的排法是每拍 1.7 s） |
| 提示词检查说第一镜 430 词超标，可分镜里这一镜只写了一个动作 | 脚本出的提示词，单镜上限只数分镜为这一镜写的内容；场景、站位、外貌、结束状态是脚本加的，不算。每镜自己的词数记在 `.media.json` 里 |
| 字幕对时明明跑过，混音还说「先去跑对时」 | 现在区分三种情况：没对过时 / 对过但没听到（说明再跑一遍没用，去听，确实说了就手填时间加 `"locked": true`）/ 区间太短量不出来。手动锁定的句子混音按人声区间算 |
| 默认的精修路线各处说法不一 | 统一成：默认从草稿存下的 latent 开始，没存才同 seed 重跑 |
| 首帧的身份参考，一处说先用 face、一处说先用半身照 | 统一成先 `face.png`，没有再用半身照（脚本一直是这个顺序） |
| 要营利时该用 Z-Image-Turbo，但没有工作流，出图清单也只出 Qwen 的命令 | 新增 `zimage_turbo_t2i.api.json`（官方模板 `image_z_image_turbo_int8` 导出，只清空提示词、固定种子），`plan_stills.py --t2i zimage` 按它出命令，`fetch_models.py --sets zimage` 查和下模型。通过了真实服务器的校验，没有出过图 |
| `observe_take.py` 提示里的命令写的是 `python3 observe_take.py` | 改成带脚本完整路径的 `python …`，路径里有空格时加引号 |

它指出的四句不实的话也都改了：「节奏检查和分镜表用的是同一个数」（当时不是，现在是）、「之后精修只能走 `--from-latent`」、「校验有错误时不出」（实际是缺文件的那一段不出、其余照出）、联络表有「最后一帧」（标了 `end_hold` 的段没有，那一帧会被裁掉）。

顺手改的：精修工作流的片段不给 `--tag` 时默认放进 `<段>_refine_<seed>`，不会把草稿挤进 `_prev_…`。

## 这一轮没有做的

- 真权重下的一切：画面、口型、耗时、显存；Sage 的两个节点；N 卡上默认的 DynamicVRAM 路径。
- Z-Image-Turbo 没有出过图；母版排 2048×1152 是保守的取值，更大的尺寸没试。
- 「二采放大超过 1.75 倍会偏软」是按二采保留一采结构的原理写的 advice，没有量过。
- 身份门禁、内容判断：替身图里没有脸，随机权重出的画面是噪声。
- Windows 上没有跑过。
