# 迭代 4：后期链路的独立可用性测试（2026-11-21）

**做法**：请一个没有任何上下文的 agent，只读 `SKILL.md` 与它指到的 reference，对一支真实的 5 段 H3 片段完成用户会提的任务——「检查这些片段，告诉我哪些有问题，再给我一版烧好字幕的成片和能在剪辑软件里打开的工程」。无 GPU、无 ComfyUI、无角色参考图。它被要求只用 skill 的脚本，并如实报告每一处文档不清、与脚本行为矛盾或需要猜的地方。

**结果**：任务完成（成片、字幕、OTIO / FCP7 XML / CMX3600、剪映草稿都交付，成片通过验收），共运行 23 步、上报 27 条摩擦点和 6 处「输出看起来不对」。其中属于脚本缺陷的 9 条：

| 发现 | 性质 | 修复 |
|------|------|------|
| `export_capcut_draft.py --mix` 在 899 帧时崩溃（库把素材时长取整到毫秒，按帧算出的时长多出 0.3 ms），且留下半成品草稿 | 缺陷 | 所有素材区间按库报告的时长裁剪；失败时清掉半成品；`selfcheck.py` 现在带 `--mix / --report` 跑 |
| 烧录字幕在起点不落在整数秒的段上晚 / 早一帧 | 缺陷 | 段内偏移改用整数帧；ASS / SRT 时间改为向下取整。逐帧比对：偏差 0 |
| QC 命令的 `--freeze-tail 1.0` 把每段最后一秒排除在检查之外，而剪辑单只在标了 `end_hold` 的段裁掉它——没标的段最后一秒未经检查就进了成片（s01 尾部混入的一帧因此漏报） | 缺陷 | 三个 QC 脚本改为只在声明了 `end_hold` 的段排除定格尾 |
| 字幕时间不准：识别器把首字放进人声前的静音，字幕早出 0.4–1.2 s，且没有任何一句被标为待复核 | 缺陷 | 按语音频段能量把起止点收回到人声；新增 `low_confidence` / `timing_suspect` 标记 |
| 片段画面里已经烧着字幕，没有任何脚本发现，`--ass` 又叠了一层 | 缺失 | 新增烧字检测（`qc_probe.py` 警告，`mix_episode.py --ass` 警告会叠字） |
| 手改的字幕时间会被下次 `retime_subtitles.py` 覆盖 | 缺失 | 句子上加 `"locked": true` 即保留；切点变动后字幕过期会被检出并警告 |
| 联络表不含最后一帧和被报跳变的那一帧，无法据此复核 WARN | 缺陷 | 两者都进联络表 |
| 新镜头以剧烈运动开场时，切点被定位晚 2 帧 | 缺陷 | 定位改用「前两帧对后两帧，减去各自内部的变化」 |
| 峰值 −0.8 dB 被判 FAIL，但并未削波，混音也会重新定电平 | 口径 | FAIL 只留给真正的削波（采样卡在满幅），峰值偏高降为 WARN |

其余为文档问题，已改：命令没写 `python` 前缀与工作目录、如何把片段变成「选片」没写、改了剪辑单之后要重跑哪些步骤没写、PROVISIONAL 没定义、缺审片记录模板（新增 `assets/review-template.md`）、字体默认值只适用于 Windows、`lines[].start / end` 的基准没写明、`--stems-out` 路径前后不一、只做后期时的入口与所需的最小分镜字段没写、引用的 `docs/` 不随 skill 安装等。另外测试暴露了两处我自己的失误：上一版安装包里混入了一个名为 `--help` 的多余文件夹（脚本把 `--help` 当成了输出目录），以及运行脚本会在 skill 目录里留下 `__pycache__`——都已消除。
